开始使用
1. 把整个 ZIP 解压到一个普通文件夹，例如 D:\Apps\Cyberboard Studio。
2. 双击 Cyberboard Studio.exe。请保留同目录所有 DLL 与 resources 文件夹。
3. 如果提示缺少 WebView2，运行 Dependencies\MicrosoftEdgeWebview2Setup.exe，
   按 Microsoft 安装向导完成后，重新打开应用。此步骤需要网络。

推荐使用 Windows 11 x64。此包也面向仍受 .NET 10 支持的 Windows 10 LTSC/
Enterprise 版本；普通 Windows 10、ARM64 原生版和 32 位版尚未验证。
无需安装 Python、CLI 或 .NET：这些运行组件已附在软件包中。
本应用尚未进行商业代码签名。请使用本包提供的 SHA256SUMS 和发布校验文件
核对来源；本包不会设置防火墙、自动启动、计划任务或自动升级。

AI 灯效制作
1. 在左侧工作空间“模型配置”选择服务、区域和模型，填写 API Key 并保存。
   API Key 默认隐藏，旁边“显示/隐藏”可查看输入或当前服务已保存的 Key，无需额外确认。
   切换服务或离开本页时恢复隐藏；隐藏保留正在输入的新 Key。
   这个页面与“灯效工作台”并列，工作台“模型配置 ↗”也会跳转到这里。
   默认服务为 Kimi Code 会员，模型 k3；Code 下拉可选 k3、k3-256k、
   kimi-for-coding、kimi-for-coding-highspeed。开放平台默认 kimi-k3；
   两种服务都可选择“自定义模型…”填写其他有权限的官方模型 ID。
   中国区/国际区使用各自官方地址，Code 与开放平台的 Key 和额度不能混用。
   旧默认连接如提示已更新到 K3，核对选择；想继续原模型，选回后保存。
   MiniMax 默认 MiniMax-M3，DeepSeek 默认 deepseek-flash；各服务独立保存
   模型、区域和密钥。修改下拉框后需“保存并使用”，工作台才切换服务。
   保存只改本机设置，测试或制作才调用服务。
2. 可点“测试连接”。测试只查询模型列表，不提交内容生成请求，也不保证每个
   模型都有权限。MiniMax 若无模型列表接口，会明确提示尚未确认，不假报成功。
   回工作台，在预览下方常驻的 AI 创作区写描述；视觉模型可添加 1–3 张参考图。
3. 支持 PNG/JPEG/WebP/GIF 第一帧；原图每张最多 20 MiB、约 3200 万像素。
   本地去 EXIF/GPS，转为最长边 1280 像素、每张不超过 400 KiB 的 JPEG。
   图片只在当前会话保存，不进草稿/作品/导出，重开 App 后需要重新选择。
4. 在 AI 创作区用简短描述开始，再点击制作按钮（显示已保存的服务名称）。
   无图例如“橙红火焰从底部窜起，轴灯像余烬，4秒循环”；有图例如
   “让图里的猫眨眼，保留橙白配色，轴灯柔和呼吸”，也可只选图片。
   新作品自动编排节奏与循环时长，可直接写“4秒循环”，不沿用当前预览速度。
   默认不发送旧作品名称、描述或配色；如需参考它的风格，在“更多工具”中
   勾选“使用当前作品风格”（默认关闭）。示例只填文字不生成。
   角色/标志可使用有限像素图，保留最多 40×64 的轮廓，通过上下滚动显示
   超出五行的部分，而不是把完整角色压扁；轴灯独立呼应。不执行模型代码。
   AI 根据素材重新编排命名、图案和转场，本地展开并检查帧数据与基本可见性。
   成功后先预览，满意再放入槽位、查看计划并明确同步。
5. 制作时可取消；失败保留原作品和描述，不添加半成品。配方或基本可见性检查
   不通过时，最多额外请求一次修复；仍不通过则拒绝入库。这些检查不评价审美、
   不保证还原图片，仍需预览完整循环。已提交请求即使取消/失败仍可能扣额度或计费。

生成只发送本次描述与所选压缩图像；勾选风格选项后才发送当前作品名称、
描述和参考配色。图片原文件名/路径、键位、设备配置或整份草稿不会发送。
API Key 保存在工作室数据目录的 ai-keys\<provider>.key，每个服务独立保存为
UTF-8 文本；界面默认隐藏，可用显示按钮查看，不再添加加密或系统授权步骤。
ai-settings.json 只有当前服务和各服务的地址/模型，不含 Key。不要把密钥发到
聊天、作品 JSON 或公开仓库；可在“模型配置”移除当前服务密钥。
旧版 credentials\<provider>.dpapi 文件保留，能读取时自动迁移到新文件，不删除旧文件。
Kimi Code 是会员编程接口，官方推荐产品集成使用开放平台；本应用保持真实
客户端身份，接口拒绝此客户端时请使用官方支持接入或切换开放平台，不伪装。
MiniMax M3 / M3.1 Flash 与 DeepSeek Flash 支持图片；Pro / M2.7 等文字
模型及未知自定义 MiniMax / DeepSeek 模型不能带图制作。M3.1 Flash 需对应套餐权限。
旧版密钥无法读取时，可为该服务重新输入并保存；其他服务仍可继续使用。
保存失败会恢复该服务原文件和原配置，不会切换到未完成的连接。
macOS 已实际验证 Code 密钥保存、连接检查，以及 k3 配合参考图在线生成；
各账号的模型权限仍以平台和自己的测试结果为准。
官方说明：https://www.kimi.com/code/docs/
开放平台：https://platform.kimi.com/docs/get-api-key

作品命名与回收站
• 自定义作品可在工作台“作品名称”输入 1–60 个字符并“保存”；作品卡片的
  “重命名”跳转到此处。内置作品保留原名，先生成模板变体才能另行命名。
• 作品导出默认使用显示名称，例如 月光海浪.design.json，文件名非法字符会
  替换；改名不改变 RGB 或已写入键盘的灯效。
• 所有作品（包括内置作品）都可“移入回收站”，会取消引用它的待同步草稿，
  不影响已经写入键盘的灯效。本机移除的内置作品不会在重启后自动补回。
  在“回收站”点“恢复作品”只恢复作品，槽位草稿需要重新放入。
• “永久删除”或“清空回收站”会先明确确认，取消不删；永久清理后无法从
  回收站恢复。在用自定义作品最多 30 套，内置作品不占此额度。
  回收站最多 30 套（内置与自定义合计）；回收站满时
  停止移入，不自动丢弃。工作台总数据最多 32 MiB（含回收站），软删除不会
  减少总大小。接近上限先导出备份，再明确永久清理不需要的作品。

首次配置（没有这把键盘的完整记录）
Windows 包不预置任何人的设备配置。选择作品并放入槽位草稿，点同步，
在缺少记录的提示中点“准备首次配置”。核对三槽：所选草稿写入目标槽，
其他槽停用、黑屏。内置模式采用官网标准方案：电量、马赛克、时钟开启，
文字与流光按官网默认保持关闭；不是原配置读回或原始出厂配置。
旧灯效、独立宏、交换键和换键表等定义无法保留，特殊按键功能可能需要重设。
App 读取并原样写入当前全部 1400 键码，执行前再核对，完成后读回校验。
键码快照不是原完整备份。勾选确认替换范围，再点“建立配置并同步”；
设备确认和完整键码核对通过后才保存完整记录，以后可正常单槽同步。
失败或本机记录未保存时，请保留计划按提示处理，不要盲目再次初始化。

先读取 JSON，只恢复指定内置模式
1. 打开“设备与槽位”，点“读取配置 JSON”。来源为本机上次成功写入记录
   加本次设备完整键码；灯效不是从硬件重新读回。可导出加载的 JSON 备份。
2. 勾选要恢复的内置模式，或点“恢复官网标准内置模式”快速选中电量、
   马赛克、时钟；该按钮只选择范围，再点“准备修改计划”。
3. 核对所选页面、字段差异及完整备份，再同步。其他页面、自定义槽位、
   当前键码与槽位草稿保留，不会重新初始化或覆盖其他 AI 灯效。
读取后配置变动会要求重读。已有记录含 CLI 不能编码的有效功能时停止写入，
可导出 JSON 交给官方工具。早期首次配置丢失电量、时钟时按此流程恢复。

从 Mac 带入这把实体键盘原来的配置（保留其他灯效与模式）
Windows 包不预置任何人的设备配置或历史。键盘不能读回灯效像素，所以
需要迁移这把键盘此前通过 CLI 成功写入后保存的完整记录，才能保留其他
槽位的灯效与扩展配置；键位另从设备当前完整读取。普通“导入灯效”只添加
作品，不建立原配置记录。不是同一把实体键盘时，请勿使用这份记录。

1. 在 Mac 关闭 App 和 CLI，在 Finder 按 Command+Shift+G，输入：
   ~/.local/share/cyberboard-cli/devices/
   打开这把键盘实际产品 ID 的目录。R6 通常为 AM01R6；R4 以实际 ID 为准。
   复制目录内 current.json 与 meta.json，保持它们放在原产品目录中。
   如以前显式设置过 CYBERBOARD_DATA_DIR，使用当时指定的记录目录。
   不要改写 meta.json。Mac App 已带后台，无需另找开发目录里的 CLI。
2. 把这个文件夹带到 Windows（例如用 U 盘），关闭 App。
3. 双击“迁移原配置.cmd”，粘贴设备文件夹或 current.json 的完整路径。
   工具校验完整结构与编码 CRC，拒绝覆盖已存在的当前库；只复制本机记录，
   不探测或写入 USB，不复制锁文件或旧操作计划。
4. 重新打开 App，点击“检查连接”。确认读到正确设备后，即可准备同步。
   新版计划保留迁移记录的灯效/其他配置，并重新读取全部当前键码作为键位。
   旧记录与设备键码有差异时，不会为改灯效把按键改回旧值或要求先重置按键。

USB 连接
• 用能传输数据的 USB 线连接键盘，先关闭其他正在占用键盘的配置软件。
• Windows 通过 COM 口识别设备（例如 COM12），并核对真实键盘产品身份。
• 单个 COM 口通信超时或失败不会中断其余端口检测。没有找到可用键盘时，
  提示会列出失败端口；已识别键盘但键位查询失败时，仍保持未连接状态。
  关闭 AM_Master、其他配置软件和 CLI，重接 USB 后再检查，作品与草稿保留。
• 如果未发现设备，检查 Windows 设备管理器的“端口（COM 和 LPT）”。
  本软件不随包安装第三方 USB 驱动；请使用硬件厂商提供的驱动说明。
• 同步时保持 USB 连接，等待设备提交和键位校验完成；应用会阻止中途刷新/退出。

只同步一个槽位
1. 在右侧选择作品和参数，点击底部 01/02/03 槽位卡选择目标，放入或更新草稿。
   点击卡片只选择放入目标，不改变正在设计的作品；卡中的“预览”才查看该槽内容。
2. 有草稿时可点“更新槽位 0N 草稿”；检查到在线键盘后，点“同步槽位 0N”，
   或设备页草稿行的“同步此槽位”，核对计划只列此槽。
3. 确认后点“同步到键盘”。成功只清除本次槽位的草稿，其他草稿继续保留。
如果要一起写多个待同步槽位，明确点“同步全部 (N)”；工作台仅在多份草稿时显示，
未准备的槽位不加入。草稿可在底部卡片“撤销草稿”；设备页也保留草稿管理入口。
所有方式都先生成备份和计划，底层传完整合并配置；其他槽位依赖可信原记录。

新版计划怎样保留键位
• 准备时完整读取设备的 7×200=1400 个键码，与原记录的灯效、其他槽位和
  扩展配置合并，再替换所选灯效。计划说明键位来自当前设备、旧记录差异，
  以及本次按键重映射为零；旧记录的差异不表示这次要修改按键。
• “刷新连接”只更新读取结果，不改键盘，也不更新磁盘 current.json。
  准备计划会保存备份/计划文件，不写 USB 配置，不更新真正的当前配置记录。
• 升级前准备的旧格式计划需关闭后重新准备。执行前重新核对原记录、设备
  身份/固件及完整当前键位，任何变化都要求重新准备。
• 只有设备确认且全部 1400 个键码与保留的当前键位读回一致后，才记录本次
  成功目标；只核对实体按键或只收到确认不算完成。灯效像素仍无法 USB 读回。
• 旧版“键位与原记录不一致”可能来自内部未映射矩阵位置。无需手工改矩阵、
  重置按键或反复刷新；用新版重新准备，保留设备当前键位即可。

本机数据
• 工作台、回收站与备份：%LOCALAPPDATA%\Cyberboard Studio
• CLI 设备记录：%LOCALAPPDATA%\cyberboard-cli\devices
• 如显式设置了 CYBERBOARD_DATA_DIR，CLI 设备记录跟随该目录。
• 出错日志：%LOCALAPPDATA%\Cyberboard Studio\logs\host.log
• 模型服务元信息：%LOCALAPPDATA%\Cyberboard Studio\ai-settings.json（无密钥）
• 模型密钥：%LOCALAPPDATA%\Cyberboard Studio\ai-keys\<provider>.key（UTF-8 文本）
• 旧版密钥：%LOCALAPPDATA%\Cyberboard Studio\credentials\<provider>.dpapi（只读迁移兼容）
删除或替换解压目录不会删除这些用户数据。

打开失败 / Unknown Hard Error
• “检查运行环境.cmd”仅检查 Python、CLI、时区和存储，不能验证 .NET 主程序启动。
• 先关闭已有 Studio 窗口，在 EXE 同目录双击“诊断启动.cmd”。
  此工具也可单独复制到旧版 0.2.2 的应用目录，诊断时不必覆盖旧包。
• 控制台会给出 %TEMP%\Cyberboard-Studio-startup-日期-随机编号 的报告目录。
  保留 summary.txt、app-host-trace.log、app-stdout.txt、app-stderr.txt，
  新版还会生成 probe-*，区分托管运行时探测和正常窗口启动。
• 若 App 打开，关闭窗口后查看报告。超过15秒仍运行只表示尚未判定，
  可能有系统错误弹框等待处理；工具不会强制关闭进程。
• 只收集系统版本/架构、固定组件哈希及本次启动输出，不读 Key、工作台、
  原 host.log，不访问 USB，也不修改系统设置。追踪可能包含本地安装路径。
• 软件自带 .NET 运行组件；不能仅凭该错误认定需要另外安装 .NET。
