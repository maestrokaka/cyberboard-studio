# 键位编辑与 AI 语音输入

本页介绍 MiaoCall Beta 14 以来的键位编辑与 AI 输入框语音。Mac 私有 Tasks Beta 3 延续这些功能；Windows Private Beta 1 已接入对应实现，但真实录音、快捷键与 USB 仍待实机验收。Windows 安装与 Codex 连接请看 [Windows 指南](MIAOCALL_WINDOWS.md)，通用任务见 [任务说明](MIAOCALL_TASKS.md)。历史 Windows RC2 不包含这些新增功能。

## 键位编辑

侧栏「键盘」组新增独立「键位编辑」。基础层、Fn 层和其余五层均按 81 个实体键展示；显示按键、媒体、灯光、无线和层功能的可读名称，原始键码放在详情中。功能名称依据随 App 内置 CLI 的字典，不表示每种固件功能都已实机验收。

1. 连接 USB，点击「读取设备键位」。离线时可看缓存或继续草稿，但不能把缓存当成实时设备。
2. 选择层和实体按键，搜索功能或选择组合键。修改先进入本机草稿，支持撤销和全部重置；草稿会随工作区保存。
3. 准备键位计划，核对每项「原功能 → 新功能」，明确勾选并确认后才写入键盘。

CLI 修改一个键也会传输完整配置，因此必须有本机已验证的灯效配置记录。设备键码、设备型号或固件与编辑基底不一致时，计划会停止；读取新基底不会静默丢弃旧草稿。未知码、内部位置、其他键层和灯效保持原样。Fn 层矩阵编辑与独立 Fn/宏扩展表不是同一能力，当前不提供宏编辑。

设备成功确认后，全部 1400 个键码读回校验。现有灯效历史恢复仍只恢复灯效，不能用它声称已恢复旧键位。此次开发验证使用合成设备，未实际写入用户键盘。

## AI 创作语音输入

在「模型配置」的「语音转文字」中单独选择服务和模型，保存语音 Key。当前接入：

- MiniMax：`asr-1.0`，中国区或国际区。
- 千问：`qwen3-asr-flash`，中国区或国际区（新加坡）。
- OpenAI：`gpt-transcribe`、`gpt-4o-mini-transcribe`、`gpt-4o-transcribe`、`whisper-1`。

语音识别有独立额度。Kimi、MiniMax、DeepSeek 的灯效创作连接不会自动作为 ASR 凭据；识别后的文字可交给任意已配置的创作模型。只为明确支持 ASR 的目录模型开放录音，不根据图片能力推测语音能力。

回到「AI 创作」，点击「语音输入」，讲话后点击「结束录音」。首次使用需要系统麦克风许可。每段最多 60 秒；录音结束后提交所选识别服务，将文字插入当前光标或替换已选文字。检查、修改后点击「发送并制作」才会开始生成灯效。

「取消输入」或 Escape 会释放麦克风、终止对应的本地识别进程并忽略迟来的结果。已提交云端的请求可能已计费。超出输入框容量的结果保留在可复制区域；失败保持原文字。录音期间阻止会话/页面和设备操作切换，避免误插入其他会话。退出或重载会先释放录音资源，再等待工作区保存。

原始录音只临时使用：Windows 在内存中，macOS 的临时音频在停止、取消、失败或退出时清除。不进入会话、作品、日志或发布包。识别后的文字沿正常创作草稿保存。语音 Key 直接在本机保存，默认隐藏、点击显示；没有新增 Keychain、DPAPI 或查看确认。

## 连接依据与验证边界

语音适配依据各服务的官方 ASR 接口。输入框录音不会自动开启全局热键；喵唤物理按键有独立开关，默认关闭。[千问接口](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference) · [OpenAI 接口](https://developers.openai.com/api/docs/guides/speech-to-text) · [MiniMax 接口](https://platform.minimax.cn/docs/api-reference/speech-to-text)

已验证合成录音、语音服务请求协议、响应完整性与限额、取消/过时结果、会话隔离、草稿保存、Key 服务隔离与保存失败回滚；两平台原生宿主已编译，Mac 录音生命周期与 Windows 缓冲/取消测试通过。MiniMax 两段合成样本已通过实际签名包识别；这不替代用户麦克风环境、其他 ASR 账户及键位 USB 写入的实机验收。
