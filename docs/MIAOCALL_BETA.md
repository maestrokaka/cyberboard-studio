# 喵唤 MiaoCall · Beta 14 公开测试版

当前下载：[MiaoCall Beta 14（macOS Apple Silicon）](https://github.com/maestrokaka/cyberboard-studio/releases/tag/v1.0.0-miaocall.beta.14-public) · [版本更新说明](RELEASE_NOTES_MIAOCALL_BETA14.md)

按住键盘左上方的「·」说话，松开后识别，确认文字后交给 Codex。喵娘在桌面上显示聆听、识别、思考、执行和结果；取消或任务结束后收起。

此版本已在 Cyberboard Studio 公开仓库分发，新包仅提供 macOS Apple Silicon。首次运行和每次重开时，物理快捷键均为关闭状态。

「AI 创作」是首页；「喵唤 · Beta」可从左侧设置分组进入。桌面喵娘可以直接拖动到屏幕任意位置，设置页里的角色图仅作静态展示。

## 界面风格

在左下角「设置 → 界面风格」选择「经典深色」或「暖岛浅色」。即时生效，关闭重开后沿用选择；原有安装默认保留经典深色。风格只影响界面和照片周围的背景，不改变作品 RGB、灯效时序、键位或槽位内容。

## 开始使用

1. 安装并登录本机 Codex 与 Spotify，保持网络可用。
2. 打开「模型配置 → 语音转文字」，选择 MiniMax、`asr-1.0` 和密钥对应区域，填写有语音识别权限的 Key，点击保存。也可选择千问或 OpenAI 的语音模型。语音服务与灯效创作模型分别配置。
3. 打开「喵唤 · Beta」。示例已填写周杰伦《晴天》的 Spotify 歌曲链接。换歌时填写名称、歌手和分享链接。
4. 开启「按键唤起」，按 macOS 提示允许麦克风和全局按键访问。首次操作 Spotify 还需要允许本 App 控制 Spotify。若系统拒绝访问，在系统设置中为此 Beta App 开启相应权限后重试。
5. 按住物理「·」，说「打开 Spotify，播放周杰伦的晴天」，松开。默认先展示可编辑文字，确认后执行。也可使用页内「按住试说一句」测试麦克风链路。
6. 修改歌曲或「识别后先确认文字」后，点击「应用到快捷键」。页面会标明尚未应用的修改。

关闭开关后，App 释放按键监听，「·」恢复正常输入。带 Command、Control、Option、Shift 或 Fn 的组合键不被喵唤截获。按 Esc 或点「取消任务」可中止当前流程。

桌面喵娘浮层可以直接拖动到合适的位置。位置会保存在本机，下一次任务显示时沿用；如果屏幕布局改变，App 会把它自动收回当前屏幕的可见区域。

## 当前支持范围

| 能力 | 此 Beta 状态 |
| --- | --- |
| macOS 按住物理按键、语音识别、顶层喵娘 | 已实现；需系统权限 |
| MiniMax `asr-1.0` | 已接入中国区 / 国际区接口 |
| AI 创作输入框语音转文字 | 已接入；识别后由用户发送 |
| Codex | 官方本机 app-server，独立临时任务 |
| Spotify | 播放已填写的歌曲链接并核对实际播放状态 |
| WorkBuddy | 下一步接入；界面占位 |
| 千问办公 / 豆包工作 | 规划占位 |
| Windows 全局快捷键、桌面浮层 | 此 Beta 不提供 |
| 全曲库语音搜索、任意桌面操作 | 此 Beta 不提供 |

本轮只向 Codex 提供歌曲播放和播放状态两个工具。歌曲链接必须来自当前填写的目录；未知歌曲不会被猜成另一首播放。只有 Codex 返回正式完成、Spotify 回读为目标歌曲且播放进度实际前进，才展示完成。模型回复、打开应用或发出播放命令本身都不算任务完成。播放可能受 Spotify 登录、地区和账户限制影响。

## macOS 本地签名与授权

当前 Beta 使用临时本机签名。代码、网页资源或图片重新打包并签名后，macOS 可能把它视为新的程序身份，旧权限需要重新绑定到当前包。请固定使用同一份已签名 App；授权后不要覆盖资源或重新签名。如果开关已开但仍被拒绝，先完全退出 App，再在系统设置中移除失效条目、重新添加当前包，并重新打开 App。不要修改系统权限数据库或放宽签名校验来绕过授权。

维护顺序为：源码与测试完成 → 冻结整包资源 → 签名和记录摘要 → 授权与实际验收。[Apple 签名要求说明](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)。

## 本机数据

API Key 按服务保存在 App 的普通本机文件中，默认隐藏，点击显示即可查看。不会使用系统钥匙串或额外查看确认。Key 不进入作品、导出、日志、软件包或 GitHub。

录音最长 60 秒；只在明确启动录音后采集，并发送给已保存的语音服务。确认的文字交给本机 Codex；其官方客户端自行处理登录，App 不读取认证文件或接管已有聊天。录音不存入作品库或工作区，临时录音在结束/取消后清理。当前任务不做持久化聊天历史。

Beta 使用独立应用标识，沿用本机 Cyberboard Studio 的作品与模型设置。它不会自动同步键盘、改键或更新固件。键位编辑与灯效同步仍各自需要完整审核步骤。

## 验证边界

离线检查涵盖 ASR 请求格式与错误、取消和迟到回复、开启并发、物理按键状态机、模型工具边界、播放回执、工作区与原预览比例。合成宿主回执的模型协议测试不等同真实播放。演示的 App、Codex、Spotify 与系统音频另行实测，按键开场明确为操作示意。

官方接口资料：[MiniMax 语音识别](https://platform.minimax.cn/docs/api-reference/speech-to-text)、[Codex app-server](https://learn.chatgpt.com/docs/app-server)。Spotify 使用已安装客户端自带的脚本接口。

## 语音连接故障排查

此前软件包漏带 TLS 校验文件，会在实际联网前失败并被误报为「连接失败或超时」。此问题已在 Beta 8 修复，AI 创作的语音输入和喵唤共用的后台同时更新。遇到旧提示时先确认使用 Beta 8 或更新的软件包；无需因为这一漏包问题重新填写 Key。

Beta 7 会在语音请求失败时区分 DNS、连接/读取超时、TLS、连接被拒绝、连接中断、服务端超时和一般网络不可达，并在桌面提示里给出对应建议。模型配置仍需选择与 Key 一致的区域及 `asr-1.0`。先用较短语句测试；如果提示超时，检查当前网络、系统代理或 VPN；如果提示 DNS，检查域名解析；如果提示 TLS，检查系统时间及 HTTPS 检查代理。HTTP 鉴权或额度错误会继续单独提示。

App 不会自动重发失败的录音。故障信息只包含诊断类别与模型配置摘要，不包含录音、转写文本、Key 或服务端响应。Beta 6 及更早版本只显示统一错误，无法追溯之前截图中的具体原因。
