# R6 声音、键位与设备配置

适用于 Cyberboard Studio `1.0.0-beta.15`。R6 声音与高级键位是新增测试能力；普通灯效工作室仍支持 R4/R6。功能按实际连接型号与完整读取结果开放，选择预览外观不会改变连接设备。

## 使用前

使用数据线将键盘直接连接到电脑。当前设备操作使用 USB CDC 串口，官网和 App 不应同时占用同一个串口；如官网已连接，请先在官网断开，再回 App 检查连接。

普通灯效同步、声音设置、单键和高级表是不同操作。打开 App、切换页面、检查连接或安装更新不会自动应用页面上的默认选项，也不会主动改键、校时、校准或升级固件。

## R6 声音

打开「R6 声音」，检查声音连接。设备型号、固件和 USB 连接来自查询；方向、降噪、音色等当前实际值没有可用的已接入查询接口，所以初始显示「实际值未知」。本机上次记录或页面默认值不能冒充设备当前状态。

| 设置 | 选项 | 设置后如何确认 |
| --- | --- | --- |
| 扬声器输出 | 关闭、仅左声道、仅右声道、左右声道 | 检查设备返回的声道值 |
| 麦克风方向 | 前向、后向、全向 | 检查参数回显和接受状态，再录音比较 |
| 麦克风降噪 | 最高、稍弱、关闭 | 检查参数回显和接受状态，再试听 |
| 麦克风音色 | 常规、高亮、低频饱满 | 检查参数回显和接受状态，再试听 |

点击选项才发送独立设置指令。页面的「本次回执」表示设备接受了这次参数，不等于声学效果已测量、断电后已保存，或重连后已重新读回。失败、断线或响应不符时显示未知，并提示重新检查；不会反复自动重发。

### 前向和后向为什么可能感觉相反

命名沿用官网。当前公开页面用前向 `0x15`、后向 `0x20`、全向 `0x30`，但网页代码不能证明每版固件的实际物理朝向。页面重开时的默认选中也可能与设备实际模式不同。

测试时固定使用 AIROHAChat 输入，在同样距离与音量下分别从键盘靠用户侧、靠显示器侧说话。先明确设置一个方向，再记录结果；换另一方向重复。记录 App、键盘与固件版本。不要仅凭 SET 回执互换标签，也不要用电脑自身麦克风判断键盘的拾音方向。

## 本地麦克风试听

1. 在系统声音设置中将输入切换为键盘的 **AIROHAChat**。页面刷新后会列出音频设备并标明当前默认输入；其他设备若不能在 App 中直接选用，会提示先在系统切换。
2. 点击「开始录音」。首次使用按系统提示授权麦克风，最长录制 30 秒。
3. 点击「结束录音」，再播放试听；可暂停、重新播放或清除。
4. 离开声音页面、取消或退出时清理临时录音。

试听不调用语音转文字，也不发送音频给模型，不进入作品、会话或工作区。AI 创作与喵唤的 ASR 是独立功能，需要另行配置对应服务。系统只识别到 CYBERBOARD USB，不代表同时识别到 AIROHAChat 音频输入；没有输入设备时应先处理系统音频连接。

## 高级操作：扬声器校准

日常修改麦克风方向、降噪或音色不需要先校准扬声器。

展开高级操作，查看步骤，确认系统默认输出为 AIROHAChat，再勾选确认开始。校准会进入设备测试模式、强制开启双声道，并保持音频播放连接至少 10 秒；随后等待设备结果。官网流程使用静音 PCM 流保持音频连接，不能将这个流程当作麦克风校准。

完成后显示左右阻抗，当前采用官网的成功状态及两侧均在 5–6 Ω 范围内的判断。校准未完成、断线、输出不符或响应异常时不显示通过。

校准结束没有已确认的自动恢复旧声道流程，也未发现可依赖的独立退出测试模式指令；页面会明确提示原声道没有自动恢复。需要其他声道时，请在流程结束后主动设置。不要将校准结果请求当作无副作用的通用状态查询。

## R6 单键、长短按与宏

先在「键位编辑」读取设备，再选择普通键位或高级编辑。完整键位和可读取的高级表作为独立草稿的基底；读取不完整时，高级编辑不会用空表代替原内容。

- **普通单键**：R6 使用独立改键指令，审核时显示层、实体键、前后功能与原始码。普通 Fn 层矩阵与长短按、宏表分别处理。
- **长短按**：为一个键设置点击功能、长按功能及触发间隔；支持增加、修改和删除，删除时明确选择恢复后的普通绑定。
- **宏**：编辑按键序列和间隔，支持增加、更新、删除及删除后的普通绑定。当前限制最多 32 个宏、合计 200 个事件；不要将未验证的无线最小间隔当作所有连接模式都可用。

修改先保存在本机草稿。准备计划时核对设备、固件、完整键位和相关表基底，保存写前备份；审核后才发送。完成后重新读取完整 1400 键码及可读宏/长短按表，核对一致后再显示已验证。

这些 R6 操作不需要上传整套灯效 JSON。中断后状态未知时，先明确重新读取相关数据，再创建新计划。已发生的操作不会自动撤销；备份与计划记录用于定位和恢复，不将“重新发送”当作自动恢复。

## 同步状态的含义

| 状态 | 能说明什么 |
| --- | --- |
| 已发送 | 相应字节已经交给传输层，不代表设备已保存 |
| 设备已确认 | 收到匹配指令、格式和校验符合要求的回执 |
| 键位／表已验证 | 重新读取的完整键码或可读表与目标一致 |
| 灯效已提交 | 获得灯效写入流程的设备确认，仍不等于逐 LED RGB 回读 |
| 状态未知 | 写入可能已发生，但缺少完整确认；应先检查设备，不继续复用旧基线 |

整套灯效同步仍需已确认的本机完整基线，因为当前没有完整灯效 USB 回读。写入开始后失败或中断会使旧基线失效，避免用旧记录继续覆盖。局部灯效协议尚未完成真实硬件保留性验证，本版不默认启用，也不把官网的忽略标记当作已证明安全的实现。

## 固件升级

App 显示已查询或注明来源的固件版本，并提供官方更新入口。点击后交接到 [Angry Miao 官方 R6 更新页](https://diy.angrymiao.com/firmware/cyberboard-r6/?light=1)，由官方页面完成设备连接、版本判断与升级。

本版没有在 App 内下载并刷写未知固件。跳转前完成当前设备操作，避免两个程序同时占用串口。官网升级过程以其提示为准；App 不把打开网页视为升级完成。

## 验证范围

离线检查使用合成设备和响应，覆盖声音枚举、帧编码、CRC/回显/状态拒绝、超时与断线、键位和高级表完整性、审核绑定与异常恢复、录音清理及前端状态。它们不访问实体 USB、不开麦克风、不消耗模型额度。

仍待实机确认：R6 声音模式的物理方向、效果与断电保持；扬声器校准实际行为；AIROHAChat 录音回放；新增单键/长短按/宏 USB 写入和更多固件；局部灯效保留性；Windows 原生 GUI、快捷键、用户登录与真实任务。对应项目未验收时，不能称全部功能已实机通过。

## 协议说明

本版依据官网当前公开通信行为独立实现。声音参数使用 USB CDC 的 64 字节包，最后一字节为 CRC-8；方向参数的十进制 `21/32/48` 对应十六进制 `15/20/30`。

| 指令（十六进制） | 用途 |
| --- | --- |
| `07 06` | 设置扬声器声道 |
| `07 08` | 设置麦克风降噪 |
| `07 09` | 设置麦克风音色 |
| `07 0A` | 设置拾音方向 |
| `07 07` / `07 04` | 校准测试流程与结果请求 |

未发现的查询指令、其他枚举值、DSP 滤波器/增益参数与持久化行为保持未知，不扫描或试发保留命令。状态确认与设置指令回显分别表述，不用页面默认值代替设备实值。

局部灯效的离线范围检查位于 `backend/r6_partial_lighting.py`，候选计划明确 `executable:false`、`requiresHardwareValidation:true`。它不会注册设备写入动作；官网部分全量编译分支可能改变忽略标记，因此本版没有默认启用局部写入。
